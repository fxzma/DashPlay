# N1 USB 共享网络与主热点

在 N1 的 `brcmfmac` 上，USB 共享网络已可用时提前建立并发虚拟热点，曾出现 iPad 和安卓设备看到 SSID 却无法加入的情况。保持同一名称、密码、信道和频宽，将热点恢复到主接口后，两种客户端都能加入，CarPlay 正常。这是特定 N1 组合的现场对照，无法据此推定所有 Broadcom 固件都存在同样问题。

USB 共享模式下，本修复仅对检测到 N1 且无线驱动为 `brcmfmac` 的设备启用主热点策略：先使用主无线接口；确实找到可用手机热点、需要 Wi-Fi 上联时再建立并发接口。USB 返回或并发关联失败时恢复主接口和既有无线参数。接口转换会重建热点与接收器，客户端可能短暂断开。

切换时一并迁移 DHCP、地址、接收器、USB 转发规则及清理记录。USB 规则安装前记录实际 AP 接口，避免清理遗留规则时使用切换前的接口。Wi-Fi 并发回退仍受硬件/固件兼容性限制；自动状态机测试不能证明客户端认证成功。

USB 共享模式提供真实网络出口，DNS 不再将 Tesla 检查域名（包括百度）固定解析到盒子。投屏自有域名仍按原规则解析到本机；其他联网模式的检查域名策略保持。此改动没有硬编码公共 DNS，也不保证手机当前具有外网。

验证命令：

```sh
PYTHONPATH=scripts/onecloud:tests/onecloud python3 -m unittest test_usb_primary_ap test_usb_public_dns test_phone_uplink
```

测试使用模拟平台，覆盖启动、同信道/跨信道切换、USB 返回、关联失败、部分操作失败后的恢复、NAT 清理和 DNS 策略。Linux 权限及运行时功能应在 Linux 上验证；实机验收需另行检查客户端加入、投屏和外网访问。
